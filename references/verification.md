# 核验、状态与台账

## 状态定义

每个项目都有独立状态。`verified` 表示满足该项目指定的证据标准，不自动代表新登录测试成功。

| 状态 | 含义 |
|---|---|
| `not_requested` | 本次没有要求变更 |
| `pending` | 已要求，但尚未提交或前置步骤未完成 |
| `saved_unverified` | 页面已保存新值，仍需要归属验证或额外确认 |
| `present_not_tested` | 页面上存在相关设置，本轮没有完成其功能挑战 |
| `verified` | 达到下表所列的本项验收标准 |
| `user_action_required` | 等待用户完成验证码、可信设备或系统原生确认 |
| `restricted` | Google 当前限制了敏感操作，按实际提示交接 |
| `failed` | 页面明确说明本次变更失败 |
| `unknown` | 已提交但反馈不明确，当前证据不足以确定结果 |

整体状态：

- `complete`：所有指定项目达到约定验收标准，私密台账已同步，临时资源已复核；没有实际指定项目时使用 `no_changes_requested`。
- `partial`：部分项目已完成，其余仍待处理。
- `user_action_required`：尚未完成任何变更，当前动作需要用户接手。
- `restricted`：尚未完成任何变更，平台限制了当前操作。
- `unknown`：存在会影响凭据现状的未决提交，先回读再继续。

## 每项需要什么证据

| 项目 | 足以支持本项完成的证据 | 容易混淆的证据 |
|---|---|---|
| 恢复邮箱 | 本轮验证完成或已验证状态有明确反馈，刷新后完整地址匹配 | 仅输入、点击保存、看到新地址或没有看到待验证提示 |
| 恢复电话 | 刷新后号码匹配；若页面要求归属验证，已完成该验证 | 两步验证短信电话存在，或只看到尾号 |
| Authenticator 更换 | 新绑定挑战被接受，刷新后条目存在，新私密记录已同步 | 旧条目仍存在，或本地种子与历史摘要相同 |
| 两步验证 | 刷新总览明确显示开启 | 只看到 Authenticator、手机号或 Passkey |
| Passkey 创建 | 系统原生创建完成，Google 列表新增条目持续存在 | 点击创建、弹出系统界面、概览显示“可添加” |
| 密码更新 | 正确账号提交后有明确成功反馈，刷新后的最近修改时间与本轮一致 | 当前密码进入下一挑战，旧会话仍能看 Gmail |
| 新凭据登录 | 本轮在指定的新会话完成实际挑战，并读到预期账号身份 | 修改时间正确，或旧会话仍然有效 |

如果设置页只显示掩码，先使用页面正常提供的详情进行本地比较。完整值没有足够证据时保留未决状态，不根据掩码猜测。

为每项记录 `verification_method`，例如 `settings_reload_and_status`、`enrollment_code_accepted_and_reload`、`native_confirmation_and_list_reload`、`success_feedback_and_changed_time`。另设 `fresh_login_tested`，避免混用证据层级。

## 私密台账更新

1. 操作前读取目标账号的当前行，保存版本或受保护的摘要作为并发检查依据。
2. 将“目标值”“页面当前值”“验证状态”分开。恢复邮箱已保存但待验证时，当前值可同步为新值，验证状态仍保持 `saved_unverified`。
3. 新 TOTP 种子与新密码先进入私密的待定记录。凭据是否成为当前值，以实际变更证据为准。
4. 使用所有写入方共同遵守的独立锁文件，使锁覆盖“重新读取当前文件 → 校验版本/合并 → 原子替换”整个区间；或使用存储系统提供的版本条件写入。若没有这些能力，则先建立单写入者约定。发现相关字段变化时先合并核实。
5. 在上述保护下使用同目录受保护临时文件、`0600` 权限和原子替换，只修改目标账号涉及的字段。原子替换避免中途写坏；仅在写入前回读一次仍存在检查后被其他写入者覆盖的竞态。
6. 结果模糊时保留旧当前值和新待定值及其状态。下一次从页面回读开始，不凭记忆选一份覆盖。
7. 完成后核对目标行及非目标行，删除本次写入产生且不再需要的暂存文件。必要的历史凭据只留在用户指定的私密保留位置。

## 时间、通知与副作用

- 记录带时区的时间。网页显示、浏览器时区和操作者时区可能不同，先换算再比较。
- 新恢复信息出现不代表旧信息立即失去作用。Google 官方说明更改恢复信息后，旧信息可能在 7 天内仍被用于发送验证码。
- 某些敏感操作要求新验证方式或设备满足 Google 的等待条件，按当前提示处理；恢复信息窗口与敏感操作等待期是不同概念。
- 修改密码后多数会话会退出，但存在例外。设备列表、第三方连接和应用专用密码分别处理，不声称“改密已注销所有入口”。
- 网页 Gmail 正常但客户端认证失败，可由应用专用密码撤销等原因引起；以客户端和官方设置的直接证据诊断，不由单个报错判定账号失效。

具体条件见 [官方资料](official-sources.md)。

## 脱敏结果

公开或聊天结果采用 [结果示例](../assets/result.example.json) 的结构。使用独立虚构账号代号，避免保留真实邮箱片段、手机号尾号、环境序号、出口 IP、种子摘要或可关联历史批次的标识。

可报告：请求项目、逐项状态、匹配布尔值、验证方法、是否做了新登录、下一动作、临时资源计数。真实错误提示先去除账号和联系方式，再提炼成中性说明。

## 收尾验收

- 页面/上下文：本次临时资源已关闭且重新列出确认；用户接手的会话单独标记保留。
- 文件：不再需要的本次临时内容已移除；私密规范台账和必要审计记录按要求保留。
- 进程/端口：只检查本次创建的对象身份，不停止共享浏览器或代理。
- 回收量：宿主机临时文件字节数与 Docker 虚拟磁盘回收量分开记录；未使用 Docker 时后者为 0。
- 报告：已完成、待验证、待用户动作和结果未知分别列出。
